# Custom Domain & Automated SSL Setup

This documents how the custom domain feature works end-to-end — from a user adding a domain in the app, to SSL being automatically provisioned on the server via HestiaCP.

---

## Architecture Overview

```
User adds domain in app
        ↓
User adds DNS records at their domain registrar
        ↓
User clicks "Verify" in app → DNS TXT check passes
        ↓
ProvisionDomainSslJob dispatched to queue
        ↓
HestiaCP CLI: v-add-web-domain-alias  → adds domain as alias (serves same Laravel app)
HestiaCP CLI: v-add-letsencrypt-domain → issues Let's Encrypt SSL cert automatically
        ↓
ssl_status = 'active' in DB
        ↓
Weekly cron auto-renews certs expiring within 30 days
```

---

## Part 1 — DNS Setup (User's Responsibility)

The user must add **2 DNS records** at their domain registrar (GoDaddy, Cloudflare, Namecheap, etc.):

### 1. CNAME Record — point subdomain to your server

| Type  | Host / Name | Value               | TTL |
|-------|-------------|---------------------|-----|
| CNAME | `test`      | `url.insanedev.in`  | 300 |

> If CNAME is not allowed (e.g. on a root/apex domain), use an **A record** pointing to the server's IP address instead.

### 2. TXT Record — domain ownership verification

| Type | Host / Name   | Value                              | TTL |
|------|---------------|------------------------------------|-----|
| TXT  | `_verify.test` | `urlshort-verify-xxxxxxxxxxxxxxxx` | 300 |

The verification token is generated by the app when the domain is added and is visible on the domain detail page.

> **Why `_verify.test` and not `test`?**
> DNS does not allow a TXT record on the same name as a CNAME. Using `_verify.` prefix avoids this conflict.

## Part 2 — Server Setup (One-Time, Done by Server Admin)

### Prerequisites
- HestiaCP installed
- The main Laravel app is hosted under a HestiaCP user (e.g. `powerhouse`)
- The main domain (e.g. `url.insanedev.in`) is already configured in HestiaCP

### Step 1 — Grant sudo permissions to the HestiaCP user

As **root**, open the sudoers file:

```bash
visudo
```

Add this line at the bottom (replace `powerhouse` with your actual HestiaCP username):

```
powerhouse ALL=(ALL) NOPASSWD: /usr/local/hestia/bin/v-add-web-domain-alias, /usr/local/hestia/bin/v-add-letsencrypt-domain
```

Save and exit.

#### Verify it works

```bash
su - powerhouse
sudo /usr/local/hestia/bin/v-add-web-domain-alias
# Expected output: ERROR: Not enough arguments   ← sudo is working correctly

sudo /usr/local/hestia/bin/v-add-letsencrypt-domain
# Expected output: ERROR: Not enough arguments   ← sudo is working correctly
```

---

### Step 2 — Configure the Laravel app

Add these variables to your server's `.env` file:

```env
HESTIA_USER=powerhouse
HESTIA_MAIN_DOMAIN=url.insanedev.in
HESTIA_BIN_PATH=/usr/local/hestia/bin
```

---

### Step 3 — Set up the Queue Worker (Supervisor)

Install Supervisor:

```bash
apt install supervisor -y
```

Create the config file:

```bash
nano /etc/supervisor/conf.d/url-shortener.conf
```

Paste:

```ini
[program:url-shortener-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /home/powerhouse/web/url.insanedev.in/public_html/../artisan queue:work database --queue=default,notifications,analytics,webhooks --sleep=3 --tries=3 --max-time=3600
directory=/home/powerhouse/web/url.insanedev.in/public_html/..
autostart=true
autorestart=true
user=powerhouse
numprocs=2
redirect_stderr=true
stdout_logfile=/home/powerhouse/logs/queue-worker.log
stopwaitsecs=3600
```

Start the worker:

```bash
supervisorctl reread
supervisorctl update
supervisorctl start url-shortener-worker:*
supervisorctl status
```

---

### Step 4 — Set up the Laravel Scheduler (Cron)

```bash
crontab -e -u powerhouse
```

Add:

```
* * * * * php /home/powerhouse/web/url.insanedev.in/public_html/../artisan schedule:run >> /dev/null 2>&1
```

This single cron entry runs all scheduled commands:

| Command                          | Schedule     | Purpose                                    |
|----------------------------------|--------------|--------------------------------------------|
| `links:expire`                   | Every hour   | Soft-delete expired links                  |
| `subscriptions:trial-reminders`  | Daily 09:00  | Notify users 3 days before trial ends      |
| `subscriptions:sync`             | Daily 02:00  | Sync subscription statuses with gateway    |
| `domains:renew-ssl`              | Weekly 03:00 | Re-provision SSL certs expiring in 30 days |

## Part 3 — How it Works in the App

### Adding a Domain (User Flow)

1. User goes to **App → Domains → Add Domain**
2. Enters their domain (e.g. `test.atharvkids.in`)
3. App creates a `Domain` record with `is_verified = false` and a unique `verification_token`
4. App displays the DNS records the user must add (CNAME + TXT)

### Verifying a Domain

1. User adds the DNS records at their registrar
2. User clicks **Verify** in the app
3. App calls `dns_get_record('_verify.test.atharvkids.in', DNS_TXT)` and checks for the token
4. On success:
   - `is_verified = true`, `verified_at = now()`, `ssl_status = pending`
   - `ProvisionDomainSslJob` is dispatched to the `default` queue

### SSL Provisioning (Automated, Background)

The queued job runs two HestiaCP CLI commands:

```bash
# 1. Add domain as an alias of the main domain (serves same Laravel public_html)
sudo /usr/local/hestia/bin/v-add-web-domain-alias powerhouse url.insanedev.in test.atharvkids.in

# 2. Issue Let's Encrypt SSL (HestiaCP handles nginx config + cert automatically)
sudo /usr/local/hestia/bin/v-add-letsencrypt-domain powerhouse url.insanedev.in test.atharvkids.in no
```

On success: `ssl_status = active` in DB.
On failure: `ssl_status = failed`, job retries up to 3 times with 60s backoff.

## Part 4 — Platform Subdomains (e.g. `test.url.insanedev.in`)

These are handled differently — no per-user setup needed.

### One-time wildcard cert

```bash
# As root — issue a wildcard cert for the platform domain
certbot certonly --manual --preferred-challenges dns \
  -d "*.url.insanedev.in" -d "url.insanedev.in"
```

### HestiaCP wildcard in nginx

In HestiaCP, the nginx config for `url.insanedev.in` already handles `*.url.insanedev.in` if you add the wildcard cert to the domain's SSL settings. All subdomains route to the same Laravel app automatically.

The `RedirectController` resolves the correct domain from `Request::getHost()` by looking up the `domains` table.

## Troubleshooting

### "Permission denied" when running HestiaCP commands
- Ensure the `visudo` rule is present and the binary paths are **exact** (no trailing characters)
- Verify: `sudo /usr/local/hestia/bin/v-add-web-domain-alias` as the `powerhouse` user — should say "Not enough arguments"

### DNS TXT verification fails
- Wait 5–30 minutes for DNS propagation
- Check propagation: `nslookup -type=TXT _verify.test.atharvkids.in`
- Ensure the TXT host is `_verify.test` (not `test` or `_verify.test.atharvkids.in`)

### SSL provisioning fails (`ssl_status = failed`)
- Check Laravel logs: `tail -f /home/powerhouse/web/url.insanedev.in/public_html/../storage/logs/laravel.log`
- Check queue worker logs: `tail -f /home/powerhouse/logs/queue-worker.log`
- Manually retry: re-dispatch the job from Tinker

### Queue worker not processing jobs
```bash
supervisorctl status
supervisorctl restart url-shortener-worker:*
```
